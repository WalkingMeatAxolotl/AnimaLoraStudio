## 1. 先看结论

四篇短指南的组织方向可以保留，但**目前不宜称为已被全部历史训练验证的指南**。主要问题分三类：

1. **明确错误或契约边界不准确**：PPSF 过拟合调参方向、Huber/InfoNoise 互斥、min-SNR 作用端点、切模型族的参数覆盖、配置快照与数据快照的混淆、英文画廊触发顺序。
2. **真实数字被扩大解释**：小显存表部分数字确有日志来源，但短实验的 allocated 峰值、整卡时点读数和完整运行的最低卡容量不是同一件事；“慢 4%”也换了比较对象。
3. **经验建议被写成效果保证**：PPSF 消除风格突变、正则让触发词成为真正开关、固定 epoch 阶段、跨软件完全一致等，当前证据不足以支持如此确定的措辞。

**建议顺序：先修 A 类事实问题；再收敛 B 类保证；最后补 C 类新用户说明。** 不需要因此否定所有经验建议，更不需要本轮重写训练代码。

> 本报告检查的是文案与当前实现、历史证据是否相符，不评价各 LoRA 的实际画面优劣。没有打开训练/生成原图作视觉评估，也没有启动新训练。对于尚缺实测的条目，结论是“未证实”，不是“必然错误”。

## 3. 历史证据到底有多少

### 3.1 不能再用“上百次训练都验证过”概括

| 训练状态 | DB 记录 | 有配置快照 | 有训练监控 | 有训练日志 |
|---|---:|---:|---:|---:|
| done | 69 | 65 | 59 | 59 |
| failed | 17 | 17 | 14 | 15 |
| canceled | 38 | 26 | 23 | 23 |
| **合计** | **124** | **108** | **96** | **97** |

- 文件系统共有 **110** 份任务 YAML，但其中 **2 份不是训练任务**（696、1850）。108 份训练快照中，task 2 字段稀疏，只有 **107 份有主要训练参数**。
- 按训练快照中的显式 `model_family`：Krea 2 **45**、Anima **18**，另 **61** 条训练无快照或未声明模型族。不能把旧格式直接补成 Anima。
- 旧目录 531 份 monitor 都属于生成任务，不能算作训练曲线。
- 61 个项目/版本组合中，28 组有多次训练。同版本可以改参数、caption、图片及实现；这些不是天然受控 A/B，也不是124个互相独立的质量实验。
- 使用 PPSF 59 次、AdamW 37 次，仅表示使用分布。107 份主要配置全部 MSE，其中106份不做 loss weighting；没有本地 min-SNR/Huber 对照，rank 只覆盖32/64。

父会话重新查询了训练总量、状态、110/108的区别、96/97的覆盖及下述代表任务，结果与独立审计一致。详细字段分布、缺失ID与只读脚本见实证附件。

### 3.2 三组决定性历史记录

**① `done` 并不等于有效训练达到目标。**

| task | DB 状态/退出码 | 监控有效步/目标步 | 日志情况 |
|---|---|---|---|
| 1848 | done / 0 | **204 / 2158** | NaN/非有限值相关日志3933行；最早第78行，最后第4697行 |
| 1853 | done / 0 | **42 / 2070** | NaN/非有限值相关日志4101行；最早第74行，最后第4681行 |

来源：`studio_data/tasks/<id>/monitor/state.json` 的 `step/total_steps`，以及对应 `run.log`。这里是**匹配日志行数，不是独立NaN事件数**。有限 loss 的均值可以下降，仍不代表那些被跳过的更新有效完成。此为历史事实，不据此认定当前版本仍有同一个终态判定问题。

**② 小显存数字不是凭空生成的，但不能当硬件保证。**

- task **1672**：Krea 2、FP8文件名、LoRA32、1024、batch1/累积4、交换28层；状态 canceled，进度 **8/10**。
- `run.log:44`：训练开始前 allocated **2.19 GB**。
- `run.log:61`：训练步 allocated 峰值 **8.4 GB**，同时 reserved **10.2 GB**，整卡时点读数 **13.4 GB**。
- `run.log:63`：采样 allocated 峰值 **7.1 GB**；`:83` 的采样后整卡读数 **6.3 GB**。
- 这些支持特定实验读数，不支持将“8.4 + 固定上下文”当12GB实卡完成证明，也不能把采样后6.3GB当8GB卡冷启动到出图的峰值上限。
- 本批记录中，显式交换28层训练无 done；这**不证明当前28层不能训练**。此前failed还涉及旧实现的锁定内存保护，不能当今天的结论。

**③ 较新的完整运行进一步说明“常驻低”不等于“训练峰值低”。**

- task **3033**：Krea 2、普通LoRA64、1024、batch1、交换14层，done，**520/520步**。
- `run.log:135` 的 `peak_train_step` 为 **21.37 GB**，`:137` 的 `peak_sampling` 为 **10.76 GB**。
- 这不能归因于rank一个变量，更不能据此算出假想28层峰值；它足以说明显存表必须携带具体配置，而非只写交换层数。

### 3.3 评估很多条，不等于很多次独立质量验证

- 完成的生成任务 **2676** 条：没有逐张视觉审查，不能视为质量通过数量。
- 旧 `project_jobs` 中 **308** 个评估子任务通过 `params.task_id` 只关联 **3** 个训练task：1133、1158、1173。
- 新 `eval_sessions` **5** 条（3 done、2 failed），同属一个项目版本；64个候选、320条指标，其中 **170 done、150 skipped**。
- 后者并非全都能唯一关联某一次训练，指标的 `sample_count` 均为空。不能跨session、跨baseline、跨数据平均后声称某优化器更好。

## 4. A类：建议优先修正的事实与契约问题

以下每项都给出可确认的最小方向；编号供用户逐条回复。A01–A07的关键矛盾已由父会话进一步查源码/原始证据。

### A01 — PPSF过拟合调参方向写反

- **位置**：`training-tips.md:114`：“过拟合可试 `2.0`”。
- **证据**：`studio/domain/training.py:562–565` 明确系数越大有效学习率越大，欠拟合调高、过拟合调低；`optimizers.md:63`及tips自身127–128行也与114行矛盾。
- **建议**：改成“欠拟合可试调高；过拟合/小数据集考虑调低”。0.5、2.0只能作试验起点，不写成必然改善的最佳值。
- **原始发现**：GA-01、E07。高置信度。

### A02 — Huber与InfoNoise“可同时开”不符合当前规则

- **位置**：`training-tips.md:186`，同文`:222`却又写schema互斥。
- **证据**：`studio/domain/training.py:765–779,817–823`声明互斥，`:1110–1134`由统一validator强制；`tests/test_config_rules.py:87–107`包含该拒绝组合的测试源码。
- **建议**：明确当前配置契约禁止同时开启；存在raw MSE通道不等于UI/API允许组合。
- **原始发现**：GA-02。高置信度。本轮未运行测试，证据是规则实现与测试源码。

### A03 — min-SNR抑制端点解释反了

- **位置**：`training-tips.md:164`：“缓解 t→1 端的 loss 主导”。
- **证据**：`runtime/training/loss_weighting.py:26–30,45–50`使用 `SNR=((1-t)/t)^2`、`w=min(gamma/SNR,1)`；γ=5时，t=.01权重约.000510，t=.99为1。
- **建议**：按当前实现写“下调低t、高SNR样本权重”。论文归属、“强烈推荐”的效果依据另行标来源，不因有实现就认定本地实验支持。
- **原始发现**：GA-03。公式判断高置信度；外部研究未联网核验。

### A04 — 显式切族并不保留所有用户改过的族相关值

- **位置**：`training-tips.md:282`：“显式改过的值不会被覆盖”。
- **证据**：`studio/domain/family_switch.py:48–68`显式切族时重算路径，并无条件重置族相关默认字段；普通加载配置只补缺失字段，是不同操作。
- **建议**：明确“切族会重置族相关字段，确认框展示变更；需要保留原实验请先复制版本”。不要因此改掉公告里正确的确认框说明。
- **原始发现**：NU-02、KV-08，已去重。高置信度。

### A05 — 冻结的是训练配置，不是完整数据集

- **位置**：Studio导览`:35`“不可变任务快照”，通用训练指南`:29,33`涉及严格复现与后续草稿修改。
- **证据**：`studio/services/task_snapshot.py:6–10`明确“仅冻config，不冻caption/图/正则集”；历史3033、2933、2681的快照仍引用版本train目录。
- **建议**：首次定义为“训练配置快照”；允许继续编辑的是配置草稿，不应引导用户在任务排队/运行时改同版本图片或caption。数据对照先复制版本。训练seed、采样seed、验证划分seed分别固定；复现还需数据、模型、软件环境。
- **原始发现**：NU-01、GA-07、E08，合并。高置信度。并非“配置冻结失效”，而是范围说明过宽。

### A06 — 英文画廊自动打标的触发顺序过时

- **位置**：`getting-started.en.md:110`称Auto-generate打开后，手动打标成功立即生成。
- **证据**：`GalleryPickerDrawer.tsx:255–288`手动打标只应用prompt；`Generate.tsx:998–1013`在点击Generate后先自动打标再提交。中文同段已正确。
- **建议**：英文同步为Auto-tag；明确“点击Generate → 打标 → 提交生成”，手动打标不启动生成。
- **原始发现**：NU-03。高置信度。

### A07 — “交换28层训练只慢4%”换了比较对象

- **位置**：小显存指南`:34–43`与`training-tips.md:321–323`，表中0层为基准，28层写“慢4%”；还有“训练每步只算一遍”。
- **证据**：`docs/design/block-swap.md:511–512`的4%是**特定采样任务14层对28层**，不是0层对28层的训练吞吐。另有训练时序探针约7%/2.6%，但条件不同，且设计文档`:278–280`说明不是有效梯度的完整生产训练验证。
- **建议**：把4%放回原采样比较；无相同配置的0→28训练数据就不填固定训练百分比。解释训练也包含反向和checkpoint重算。
- **原始发现**：KV-02、E02。高置信度。不反向声称“实际开销绝不可能4%”。

### A08 — “侧栏八步”的结构与当前产品不一致

- **位置**：getting-started中英`:87–96`把测试列为项目侧栏第八步。
- **证据**：`Sidebar.tsx:453–460`为项目Dataset加六个版本步骤；`:719`的Generate是全局入口。
- **建议**：可以保留“八个操作阶段”的教程组织，但不称“侧栏八步”；训练完成后转全局测试。英文Test/Testing路径统一为实际的Generate、Settings → Generate。
- **原始发现**：NU-04/05。代码证据明确，非布局改造建议。

## 7. 明确保留、不采纳的扩大推断

**应保留：**

- 四篇指南的分工；页面地图、默认基线、单变量对照、loss不等于画面质量。
- 项目/版本/任务分层、预设复制后不持续覆盖版本配置；限定任务为配置快照即可。
- Krea使用Raw训练、Turbo供推理；官方默认路径兜底；FP8要求grad checkpoint且DoRA不兼容。
- 文本缓存、模型级显存策略与block交换的区别；普通LoRA分块merge。
- 当前LoRA/LoHa/LoKr/rs-LoRA有实现/测试源码支持的兼容路径。历史1520/2202的Float8失败**不足以否定当前兼容声明**，但也不能算本轮全组合实卡验证。
