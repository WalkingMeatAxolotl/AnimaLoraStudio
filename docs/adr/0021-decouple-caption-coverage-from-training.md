# 0021 — 将 Caption 覆盖率与训练样本入选解耦

**状态**：Accepted
**日期**：2026-10-03
**决策者**：项目维护者

## 背景

Issue #596 暴露出打标状态按 sidecar 文件存在判断的问题：空 TXT 被“跳过已有”跳过。进一步核查发现，训练扫描允许空 TXT 以空文本训练，却排除没有 sidecar 的同一张图片；即使设置了 `caption_override`，也在覆盖文本生效前丢弃图片。桶分布与 NaViT 预估复制了这个过滤，打标/编辑阶段要求 100% Caption 覆盖。

维护者确认图片入选应由训练集范围决定，Caption 只是训练条件。清空编辑内容应保存为空，不应主动删除 sidecar 或让图片退出训练。

## 候选方案

1. 清空时删除 sidecar，继续排除无 Caption 图片：状态依赖文件存在，编辑会隐式改变训练样本数量，否决。
2. 增加“允许无 Caption 训练”开关：可以表达两种策略，但增加设置并保留空文件/缺失文件的心智负担，否决。
3. 训练集图片默认入选，缺失或空 Caption 使用空文本，打标覆盖率独立统计：采纳。

## 决策

- 训练扫描不因缺少 Caption 排除图片；保留现有目录范围、repeat、分辨率、格式优先级及显式覆盖文本规则。
- TXT 缺失、空白或无有效内容都视为未打标；JSON 按现有渲染语义判断，JSON-only、自然语言描述及 `meta.trigger` 仍被支持。
- “跳过已有”仅跳过含有效内容的 Caption，预筛选与最终写入使用同一判断。
- 标签编辑保存空标签时保留同名 sidecar 和 JSON 中未编辑的字段；未保存草稿不影响磁盘状态。保存继续自动创建快照。
- Caption 提交响应附带已成功写入图片的格式与有效内容状态，以便前端正确显示仍有描述/trigger 的 JSON；不改变请求、既有返回字段、数据库或 SSE。
- Caption 覆盖率不阻止打标和编辑阶段推进；训练集为空等真实错误继续阻止推进。
- 桶分布和 NaViT 样本/步数预估不按 Caption 过滤；缓存与非缓存路径使用同一最终文本解析。日志汇总源内容为空的图片与 repeat 展开样本数量，不消耗随机增强 RNG。
- 缺失 Caption 是合法空文本输入，损坏的首选 JSON 不是；保留开训前 JSON fail-fast，不静默回退 TXT 或空文本。

本决策修订 ADR 0007 §11.5-B 中打标/编辑的 100% Caption 覆盖要求，其他状态机与检查不变。

## 理由

空文件与缺失文件不应改变图片训练资格。统一按内容判断打标状态，既支持“清空后重新打标”，也支持明确的无标签训练，不需要额外状态、删除动作或策略开关。

## 后果

- 原先会被排除的无 Caption 图片现在参与训练，实际样本数和步数可能增加；这属于有意的默认行为变化。
- 空文本仍学习图像，但不提供显式标签条件；用户应自行选择 Caption 策略。打标覆盖率及训练日志提供可见事实，不强制补齐。
- JSON 清空标签不等于清空完整训练文本：自然语言与 trigger 不被普通标签编辑隐式删除。
- 数据损坏继续明确报错，不能与合法空内容混淆。
