Two VRAM fixes for test generation: XY grids no longer run out of memory when switching LoRAs, and "Release cache" no longer fails silently

### Fixed

- **XY grids ran out of VRAM when switching LoRAs per cell with block swap enabled (#499)**
  With a Krea 2 fp8 base model and block swap enabled, every cell of a LoRA checkpoint / strength axis reloads the model. The old model was not released in time on switch, so up to three copies of the model sat in VRAM at once — even a 32GB card hit out-of-memory on the third cell. The old model is now released immediately on switch; VRAM usage matches single-image generation and grids of any size run stably.

  - The per-cell reload itself remains (that is the existing cost of block swap's memory savings) — it just no longer accumulates
- **"Release cache" did nothing after a failed generation (#499)**
  After a generation failed (e.g. out of memory), clicking "Release cache" reported success but VRAM usage did not move, and only restarting the service recovered it. A cleanup pass now runs automatically after a failure, and manual "Release cache" actually reclaims VRAM in that state too.
