Accurate step estimates under NaViT packing · the training RAM guard can now be turned off · settings descriptions tucked into ⓘ tooltips

### Added

- **The RAM guard for training and AI-generated regularization sets can now be turned off (#480)**
  New toggle under Settings → Training → Training parameters (on by default). The guard estimates whether memory will suffice from weight file sizes, and a conservative estimate can wrongly refuse to start training — you can now switch it off and proceed. The existing toggle under the inference-side "VRAM strategy" is unchanged; the two are independent, and error messages now point to the correct settings location for each side.

  - The pinned-memory guard for block swap is not affected by this toggle: exhausting pinned memory can freeze the whole machine — if it blocks you, lower the number of swapped blocks instead

### Changed

- **Inline description text in Settings has moved into the ⓘ icons (#481)**
  The small description lines under field labels are now inside the adjacent ⓘ tooltip, making the page more compact and easier to scan. Nothing was removed — hover the ⓘ to read the full description.

### Fixed

- **Step estimates on the training page are no longer half the real count under NaViT packing (#482)**
  With `navit_packing` on, one step is one token pack and `batch_size` plays no role in batching, but the estimate still divided samples by batch size — on large-image datasets this showed 2520 steps while training actually ran 5040. The estimate now runs the exact same packing simulation as training and matches the training log.

  - The total step count on the monitor page is corrected every epoch (pack counts fluctuate slightly between epochs, so the estimate keeps its ≈ prefix)
  - Under NaViT native resolution, the "bucket distribution" panel now shows the actual native-size distribution instead of resolution buckets that don't exist
  - `batch_size` is pinned to 1 under NaViT packing (it had no effect before; being adjustable was just misleading) — use `vae_cache_batch_size` to control VAE cache encoding batches
  - Enabling NaViT native resolution and then disabling NaViT packing used to make saving the config fail with no way out; it now recovers to a valid combination automatically
- **The availability check on the tagging page no longer misjudges when a non-default model or preset is selected (#478)**
  The status badge next to the tagger picker and the "Start tagging" button only consulted the global default config: picking an already-downloaded CLTagger v2 model in advanced options still showed "model download required" with the button locked, and a fully configured LLM preset still reported "base_url not set". The check now follows your current selection and re-runs after switching model versions or presets, saving settings, or finishing a model download.
