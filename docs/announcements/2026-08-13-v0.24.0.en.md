Anima training now fits 6GB GPUs · pick your compute GPU on multi-GPU machines · long captions / prompts are no longer truncated

### Added

- **Block swap now works for Anima training — full training fits 6GB-class GPUs (#490)**
  The "Block swap" field on the training page now applies to Anima: some DiT layers are swapped out to system RAM, trading time for VRAM. Swapping all 28 layers cuts peak training VRAM from 5.2GB to 1.84GB at about 11% slower steps, with identical training results.

  - Swapped layers need a matching amount of system RAM, which stays locked during training
  - The field description now lists the valid range and per-layer savings for each model family (#497)
- **Choose which GPU to compute on, on multi-GPU machines (#494)**
  A new GPU dropdown under Settings → System → Environment. Training, image generation, and AI regularization sets all follow it after a restart. The top-bar GPU monitor and the VRAM guard now track the GPU actually in use — on multi-GPU machines they could previously read a different card.

  - If you already set `CUDA_VISIBLE_DEVICES` yourself (e.g. in the launch script), your setting wins and nothing changes

### Changed

- **The generation timeline is now a single ledger — no more doubled images after a refresh (#488)**
  Each generation is one row in the timeline; parameters live in the row and images are its attachments. With "save images" on, refreshing the page used to show the same image twice — the restructure removes that possibility.

  - With "save images" on, images are now written to disk by the server — they are saved even if you close the page mid-run (previously they were lost)
  - Unsaved temporary images leave a "released" placeholder after the session ends; clicking it still restores the parameters
  - Old images saved by early versions without a task record no longer appear in the in-app list (the files on disk are untouched)
  - `.cache/disk-history-index.sqlite3` is no longer used and can be deleted
- **Full-screen image viewing is unified across the app (#492)**
  The test page, evaluation views, and step pages now share one viewer: exit via the × button, ESC, or a click on the empty canvas; a single bottom bar holds the zoom controls, caption, and counter; small images are no longer blown up to fill the viewport; the side-by-side compare mode zooms each side independently.
- **Settings → System reorganized with a new "Environment" section (#495)**
  The System tab now reads Version → Environment → Storage → Services. Environment starts with a one-line machine summary (NVIDIA driver / CUDA / platform / Python), followed by the GPU selector and collapsible rows for PyTorch / Flash Attention / xformers / ONNX Runtime — collapsed, all statuses fit one screen; rows with problems expand automatically.

  - The ONNX Runtime installer moved here from the Tagging tab; the "fix GPU acceleration" link on the tagging page jumps here and expands the right row

### Fixed

- **Captions / prompts beyond 512 tokens are no longer silently truncated (#496)**
  A long prompt that worked in ComfyUI came out clipped here — upstream's 512 is a padding floor, not a token limit, but it had been read as a limit, so the part of training captions and generation prompts beyond 512 tokens was silently dropped. Long text now takes full effect; behavior within 512 tokens is bit-for-bit unchanged, and existing text caches stay valid.

  - Very long text increases VRAM and text-cache usage linearly — budget accordingly
- **Generating no longer crashes after switching model families back and forth (#493)**
  Generating with Krea 2, switching to Anima, then back to Krea 2 reliably crashed sampling. A stale text-encoder reuse check was the cause; the text stack is now rebuilt correctly.
- **Krea 2 training crashed on startup for older installs (#489)**
  Installs from before v0.20 that upgraded in place kept an old transformers version missing a component Krea 2's text encoder needs — training, evaluation, and test generation all failed at startup. The dependency floor has been raised; the next auto-update fixes this with no manual steps.
- **A numerically bad batch during training no longer takes down its whole accumulation group (#486)**
  When a loss turned non-finite, gradients already accumulated from healthy batches in the same group were discarded, and the step counter could stop advancing. Now only the bad batch is skipped: healthy gradients are kept, steps advance normally, and monitor curves are no longer polluted by non-finite values.
