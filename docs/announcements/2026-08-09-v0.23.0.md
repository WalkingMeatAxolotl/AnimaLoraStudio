NaViT 打包下步数预估修正 · 训练内存水位保护可关闭 · 设置页说明收进 ⓘ

### 新增

- **训练和 AI 生成正则集的内存水位保护现在可以关闭（#480）**
  设置 → 训练 → 训练参数新增开关（默认开启）。水位保护按权重文件大小估算内存是否够用，估算偏保守时可能误判「内存不足」拒绝启动——遇到误判现在可以关掉它继续训练。推理侧原有的「显存策略」里的开关保持不变，两侧各自独立；相关报错的指引文字也会指向各自正确的设置位置。

  - Block 交换的 pinned 内存护栏不受此开关影响：pinned 内存占满会卡死整机，如遇拦截请调小交换层数

### 变更

- **设置项的说明小字全部收进 ⓘ 图标（#481）**
  设置页各字段标题下的行内说明文字移入旁边的 ⓘ tooltip，页面更紧凑、扫读更快。说明内容没有减少，悬停 ⓘ 即可查看。

### 修复

- **NaViT 打包下训练页的步数预估不再只有实际的一半（#482）**
  开启 `navit_packing` 时一步是一个 token 包、`batch_size` 不参与分批，但步数预估仍按「样本数 ÷ batch」计算——大图数据集下会出现预估 2520 步、实际训练 5040 步的偏差。现在预估走与训练完全相同的打包模拟，结果与训练日志一致。

  - 监控页的总步数每个 epoch 自动修正（打包数在 epoch 之间有小幅波动，所以预估值仍标 ≈）
  - NaViT 原生分辨率下「桶分布」面板改为显示真实的原生尺寸分布，不再展示实际不存在的分辨率桶
  - `batch_size` 在 NaViT 打包下固定为 1（此前也不生效，只是可调造成误导）；VAE 缓存编码批次用 `vae_cache_batch_size` 控制
  - 开了 NaViT 原生分辨率后再关掉 NaViT 打包，保存配置会一直报错且无法自救；现在自动恢复为合法组合
- **打标页选了非默认模型或预设时，可用性检查不再误判（#478）**
  此前打标器旁的红绿状态和「开始打标」按钮只看全局默认配置：CLTagger 在高级参数里选了已下载的 v2 模型仍提示「需下载模型」、按钮被锁死；LLM 打标选了已配好的预设仍报「未配置 base_url」。现在检查跟随你当前的选择，并在改选版本或预设、保存设置、模型下载完成后自动重查。
