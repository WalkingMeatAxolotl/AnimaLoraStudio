A rebuilt image-testing workflow — layered LoRA catalog · unified XY-axis editing and navigation · tag prompts from a Booru gallery · reliable dynamic zip downloads

### Added

- **Browse project outputs and external folders in one layered LoRA catalog (#523)**
  The Test page now groups Studio project checkpoints, the default LoRA folder, and custom folders as “project / source → LoRA,” with source filters, search, project-version filters, and recursive folder browsing. Click a LoRA to add or remove it; manage extra folders under Settings → Testing.
- **Pick and tag images from Danbooru or Gelbooru on the Test page (#525)**
  “Pick from gallery” in the Prompts section searches and pages by source, rating, time, and tags. Select an image to turn it into a prompt with your global WD14, CLTagger, or LLM settings, with an option to start generation as soon as tagging finishes. Studio loads remote images through its rate-limited proxy and local cache; it does not import them into the training set.

### Changed

- **XY matrices now use one axis editor and layered sidebar navigation (#524)**
  X / Y axis types, value lists, checkpoint axes, and LoRA-strength axes live in an attached drawer with drag-and-drop ordering. Single-image and XY modes share the current-LoRA panel, and the Generate button shows the total image count. Existing generation configs, history snapshots, and matrix coordinates remain compatible.
- **Prompt and configuration drawers keep their place when reopened (#525)**
  After their first open, the LoRA, XY-axis, training-prompt, and gallery drawers retain filters, scroll position, and loaded results for the current page session. Training-set prompts are also directly editable and saved with the generation config.

### Fixed

- **Multi-connection download managers no longer corrupt on-demand zip exports (#522)**
  Project exports, bundles, and task-output zips now reject Range chunking, preventing IDM, Thunder, Ghost Downloader, and similar tools from stitching together chunks produced by separate packaging runs. Exports are also written atomically, so an interrupted job cannot leave a half-written zip behind.
