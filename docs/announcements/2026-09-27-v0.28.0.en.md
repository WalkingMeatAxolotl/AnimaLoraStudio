Optional Triton training path · task-scoped random seeds · batch project management · smoother generation, queue, evaluation, and monitoring workflows

### Added

- **The announcement center now has a continuously maintained Guides category (#595)**
  Guides appear first in the filter so new and returning users can find them quickly. The initial set covers the Studio pages and workflow, general LoRA training, Krea 2 training, and Krea 2 on small GPUs. Guide entries keep stable identities and are updated in place instead of staying pinned above current migrations.
- **A restricted Triton backend is available for LoRA and LoHa (#568, #569, #572, #577)**
  Install the matched package under Settings → System → Environment, then explicitly select Triton in advanced training settings for standard LoRA or LoHa. A disposable process checks the CUDA path before training and falls back to Torch when the probe fails. Torch remains the default because testing did not show a stable speed gain. LoKr, DoRA, T-LoRA, Ortho, adapter dropout, and FlashAttention combinations are not supported. Published hardware validation currently covers Anima only.
  - A reproducible LyCORIS benchmark tool can create standalone references, replay numerical results, and compare Torch / Triton training throughput. See the [LyCORIS benchmark guide](https://github.com/WalkingMeatAxolotl/AnimaLoraStudio/blob/master/docs/user-guide/lycoris-benchmark.md).
- **Archive, restore, or permanently delete projects in batches (#591)**
  Active and archived project views now have an explicit selection mode, and searches or filters trim selections that are no longer visible. Permanent deletion explains the irreversible effects and task-archive boundary first. If some files cannot be removed, successful projects are completed while failed items stay selected for retry.

### Changed

- **`seed=0` is now randomized once per task or comparison group, then frozen (#575)**
  New training tasks freeze separate training, sampling, and validation-split seeds. Regular generation randomizes each image, while an XY grid or one evaluation session shares its comparison seed. Actual values are stored in task snapshots, generation history, and PNG metadata; retry and pause/resume keep the original values. Explicit nonzero seeds retain their reproducible behavior. See [Random seeds and reproducibility](https://github.com/WalkingMeatAxolotl/AnimaLoraStudio/blob/master/docs/user-guide/random-seeds.md).
- **Generation takes fewer repeated steps and offers better LoRA browsing (#580)**
  Gallery picks can enable Auto tag so generation first obtains the latest prompt. Switching Prompt, LoRA, or Parameters tabs keeps the current drawer open. LoRA projects and files can be sorted by activity, creation time, modification time, or name, and remove controls have larger keyboard-accessible targets.
- **The queue and task details are more reliable and easier to scan (#587)**
  Failed, loading, and genuinely empty states are distinct and support local reloads. Cancel, delete, pause, resume-training, and global scheduling holds explain their real effects before running. Task information is grouped by status, time, and source; fake progress and unreliable queue positions are gone, with better keyboard actions and source links.
- **New evaluations stay in the evaluation list with a clear task link (#593)**
  Successful creation highlights the new session instead of navigating away automatically, and “View task” opens the associated job when available. The creation dialog, metrics panel, and sample grid now use shared design-system components, with clearer checkpoint selection and keyboard focus.
- **Long-job logs and monitor timing are more accurate (#590, #592)**
  Logs show the latest 2,000 lines by default, and Load all walks back to the start while live updates continue. Completed, failed, canceled, and paused monitor timers now stop at the relevant timestamp instead of continuing to grow. Colors, focus, spacing, and motion also follow the active theme, density, and reduced-motion preference.

### Improved

- **Blocking surfaces now handle keyboard focus more consistently (#581, #582, #584–#586)**
  Image previews, the Settings drawer, and the LLM preset editor correctly receive and restore focus, keep Tab navigation inside, and prevent global search from opening over an unfinished task. Toasts remain exposed to assistive technology while Settings is open, and preset deletion or built-in restoration stays inside one dialog.
- **Collapsed navigation and semantic styling are more consistent (#579, #592, #593)**
  Existing information architecture is unchanged, while icons, read-only labels, cards, theme colors, and compact-density presentation now share the same visual roles.

### Fixed

- **Triton and FlashAttention can no longer be submitted together (#589)**
  Choosing FlashAttention pins the LyCORIS backend to Torch. Conflicting hand-written YAML is rejected, while tolerant preset repair keeps FlashAttention and restores Torch, preventing silent repeated fallback to SDPA during training.

### Upgrade notes

- This release has no required data migration. As usual, stop running jobs, close Studio, and back up `studio_data/` before updating.
- Triton is never installed or enabled automatically. Read the [experimental Triton backend guide](https://github.com/WalkingMeatAxolotl/AnimaLoraStudio/blob/master/docs/user-guide/triton-backend.md) before opting in; keep the default Torch backend for stability or strict reproducibility.
- The new `seed=0` scope takes effect automatically. Use a nonzero seed and retain the task snapshot or generation metadata when you need exact reproduction across separate tasks.
