Anima 训练下探 6GB 级显卡 · 多卡机器可选计算显卡 · 超长 caption / 提示词不再被截断

### 新增

- **Anima 训练支持 Block 交换，6GB 级显卡可跑完整训练（#490）**
  训练页的「Block 交换」现在对 Anima 生效：把部分 DiT 层换出到内存，用时间换显存。28 层全部换出实测训练峰值显存从 5.2GB 降到 1.84GB，速度约慢 11%，训练结果不受影响。

  - 换出的层需要等量内存且训练期间会被锁定，请确保内存余量充足
  - 字段说明改为按模型族标注可填范围与每层省多少显存（#497）
- **多卡机器可以选择用哪张显卡计算（#494）**
  设置 → 系统 → 环境新增「显卡」下拉，训练、出图、正则集 AI 生成全部跟随，重启后生效。顶栏的显卡监控和显存护栏也改为跟随实际在用的那张卡——此前多卡机器上可能一直读的是另一张。

  - 自己在启动脚本里设过 `CUDA_VISIBLE_DEVICES` 的用户不受影响，你的设置优先

### 变更

- **出图时间线改为单一台账，刷新后图片不再翻倍（#488）**
  每次出图在时间线里就是一条记录，参数存在记录里、图片是记录的附件。此前「保存出图」开启时刷新页面会看到同一张图出现两次，这个结构性问题已随重构消除。

  - 「保存出图」开启时，落盘改在服务端完成——即使中途关掉页面，图也会保存（此前会丢）
  - 不保存的临时图在会话结束后显示为「已释放」占位，点击仍可回填当时的参数
  - 早期版本落盘、没有任务记录的旧图不再出现在应用内列表（磁盘上的文件保留，不受影响）
  - `.cache/disk-history-index.sqlite3` 已不再使用，可手动删除
- **全站看大图统一为同一个全屏视图（#492）**
  测试页、评估和各步骤页的全屏看图现在是同一套体验：× 按钮 / ESC / 点画板空白处三种方式退出；底部一条工具栏集中缩放控件、说明与计数；小图不再被强行放大铺满；对比分屏两侧可各自独立缩放。
- **设置 → 系统页重组，新增「环境」区（#495）**
  系统 tab 按 版本 → 环境 → 存储 → 服务 排列。「环境」开头是一行机器概览（NVIDIA 驱动 / CUDA / 平台 / Python），下面是显卡选择和 PyTorch / Flash Attention / xformers / ONNX Runtime 四个依赖的折叠行——全部收起时一屏扫完状态，有问题的行自动展开。

  - ONNX Runtime 的安装修复从打标 tab 移到这里；打标页的「修 GPU 加速」入口会自动跳转并展开对应行

### 修复

- **超过 512 token 的 caption / 提示词不再被静默截断（#496）**
  同一条长 prompt 在 ComfyUI 里正常、在这边却像被砍过——上游的 512 其实是补齐下限而非上限，此前被误读成上限，训练 caption 和出图提示词超出 512 token 的部分被静默丢弃。现在完整生效；512 token 以内行为逐位不变，已有文本缓存继续有效。

  - 超长文本会线性增加显存与文本缓存占用，请按需取舍
- **测试页跨模型族来回切换后出图不再崩溃（#493）**
  先用 Krea 2 出图、切到 Anima、再切回 Krea 2 时采样必崩报错。根因是文本编码器的复用判断残留了过期状态，现在会正确重建。
- **老安装升级后 Krea 2 训练启动即崩的问题（#489）**
  v0.20 之前装机、之后原地升级的用户，transformers 停留在旧版本、缺少 Krea 2 文本编码器需要的组件，训练 / 评估 / 测试出图启动即报错。依赖下限已抬高，随下次自动更新自动修复，无需手动操作。
- **训练中单个批次数值异常不再连累整组（#486）**
  loss 出现非有限值时，此前会把同一梯度累积组里其它正常批次已算好的梯度一并丢弃，且步数可能停止推进。现在只跳过异常批次本身：正常梯度保留、步数照常推进，监控曲线也不再被异常值污染。
