Task logs rebuilt — one viewer, debug toggle, one-click diagnostics bundle, follows your UI language · import / export LLM tagging presets · several Windows training fixes

### Added

- **One log viewer across the app, with a debug toggle (#507 #508 #509)**
  Training, generation, tagging, and evaluation logs now share one experience: lines split into time / level / source columns, errors in red, warnings in yellow. Debug details are always recorded but hidden by default — flip the "debug" toggle in any log view to reveal them, no task re-run needed. The global default lives under Settings → System → Logs ("Show debug lines by default").

  - "Load earlier" paging, copy visible lines, download the full raw log
  - After a dropped connection the viewer backfills the gap — no more missing lines
  - The error summary on failed tasks now shows the last real error (with its full stack trace) instead of a generic tail of the log
- **One-click diagnostics bundle (#512)**
  A new "Diagnostics" button on the task detail page and under Settings → System → Logs packs the task log, config snapshot, environment info, and the matching time window of the server log into one zip — attach it when reporting an issue. Common secrets (api keys / tokens) are redacted automatically; still worth a quick look before sending.
- **LLM tagging presets can be imported and exported (#518)**
  The preset editor gains an "Export" button: the downloaded json contains no API information (key / endpoint / model list), so prompt recipes are safe to share. The preset list in Settings gains "Import preset": the editor opens right after import so you can fill in your own connection info, and the default preset used on the tagging page is left untouched.

  - Deleting a preset and saving a copy now show a success toast

### Changed

- **Task logs follow your UI language, and floods are throttled (#514 #516)**
  Narrative log lines (loading progress, VRAM status, step reports) now follow the UI language; warnings / errors stay in English so they are searchable and easy to paste into issues (in-app error messages are unaffected and remain bilingual).

  - Numeric anomalies during training (e.g. NaN) could flood tens of thousands of lines; now the first occurrence logs in full, later ones roll up into one line per epoch, and a run of steps with no effective update escalates to a single error
  - A batch of "errors" that actually had fallbacks were downgraded to warnings — successful tasks no longer end with red lines
  - Stopping the generation daemon normally no longer prints a yellow warning
- **The two tag-dictionary toggles moved into Settings, out of the browser (#510)**
  "Show translations on chips" and "Tag autocomplete while typing" used to live in browser storage — switching browsers or clearing site data lost them. They are now saved with the rest of your settings and travel with backups; existing values migrate automatically, nothing to do.

### Fixed

- **Multi-resolution training on Windows permanently slowed down after a bucket switch (#506)**
  With ARB multi-resolution training, the first resolution-bucket switch filled VRAM without an OOM error, and every step afterwards went through shared memory at half speed or worse. The allocator cache of the previous bucket is now returned at the switch point; speed stays flat.
- **Block swap with many layers failed at startup with "CUDA out of memory" (#511)**
  The error had nothing to do with VRAM: pinned host memory was rounded up to powers of two, inflating actual usage by about 1.5×, and swapping 28 layers on a 32GB-RAM machine hit the Windows limit of locking at most half of physical memory. Weights are now packed to their exact total, so locked memory ≈ the weights themselves; when RAM truly runs short, the error now says it is a memory-locking problem and how many layers to reduce.
- **XY comparison grids are no longer killed by the task timeout (#513)**
  The generation timeout used to cover the whole task, so a healthy XY grid with many cells — each reloading the model — could hit the limit and get terminated. The timeout is now per image: each finished image resets the countdown, and only a single image making no progress counts as a hang.
