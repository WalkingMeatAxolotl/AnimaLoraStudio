官方 fp8 底模配合 **Block 交换**可以降低 Krea 2 的显存需求。这篇帮助你选择起步配置，并区分“测到了多少显存”和“某张卡一定能跑”。**8 GB 出图、12 GB 训练仍是待目标实卡全流程验证的试用方案，不是容量保证。**

### 起步配置

底模选 **官方 fp8**（在 **设置 → 训练** 的下载中心下载，选中文件即生效）。以下分档不是所有 rank、batch、caption 长度和分辨率的通用门槛：

| 你的显存 | 训练起点 | 测试出图起点 |
|---|---|---|
| **24 GB 以上** | fp8 + gradient checkpointing；可先试不交换，峰值不足再开 | 显存策略「默认」，视峰值调整交换 |
| **16 GB** | fp8 + gradient checkpointing；交换 14 层起，不足再加到 28 | 「省显存」，按需增加交换 |
| **12 GB** | 交换 **28 层**，低 batch；仅试用方案，未完成目标实卡验证 | 「省显存」+ 交换 28 层；同样需要全流程验证 |
| **8–10 GB** | 余量风险较大，降低分辨率试验，不承诺可训练 | 「省显存」+ 交换 28 层；不能仅凭约 6 GB 的时点读数保证出图 |

内存（不是显存）也要留足：28 层 fp8 换出权重约 11 GB，需要锁定在内存里。**32 GB 总内存只是起步建议**；还要容纳操作系统、模型加载、缓存和其他程序，检查的是当前可用内存。

### Block 交换是什么、在哪里开

Krea 2 和 Anima 的 DiT 都有 28 层。Block 交换把部分层的权重放在内存，计算时换入显存，用搬运时间换显存；0.24.0 起两族都支持。

- **训练**：训练配置页打开「高级」，在 **系统与性能 → Block 交换** 设置。默认 `0`（关闭），范围 0–28。
- **测试出图**：**设置 → 测试 → 显存策略 → Block 交换**，也默认 `0`。
- 训练涉及前向、反向及 gradient checkpointing 重算；出图每个采样步也需搬运。实际开销取决于 PCIe、内存、分辨率和配置，没有通用固定百分比。
- 搬运本身不引入额外量化，但不承诺训练或成图逐位等同于不开交换。当前修复版的梯度对照在已测重复性噪声量级内。
- 修改交换层数需要重新加载模型，下一次出图的启动会更慢。

### 实测数字怎么读

以下来自 RTX 5090 环境中的 Krea 2 官方 fp8、1024²、普通 LoRA rank 32、batch 1 / 累积 4、gradient checkpointing 短实验。14 层和 28 层实验分别只到 6/10、8/10 步后取消，**不是目标小卡完整训练通过记录**。

| 换出层数 | 训练开始前 allocated | 训练步 allocated 峰值 | 采样 allocated 峰值 |
|---|---|---|---|
| 14 | 约 7.9 GB | 此表未列 | 此表未列 |
| 28 | 约 2.2 GB | 约 8.4 GB | 约 7.1 GB |

`allocated` 是 PyTorch 张量分配量；`reserved` 是分配器保留量，整卡占用还包含上下文等，不能把三种口径混为最低卡容量。28 层实验在训练后记录到 reserved 10.2 GB、整卡 13.4 GB；采样后的整卡时点读数约 6.3 GB，并非全流程峰值。另一次任务管理器扣背景读数约 6 GB，与 allocated 峰值加上下文约 8.8 GB 的估算仍有差异。

这不证明 12 GB 或 8 GB 一定失败：小卡分配器可能更积极回收。但在实卡验证前，也不能反向保证能跑。较新的 rank 64 / 14 层完整训练记录到训练步 allocated 峰值约 **21.37 GB**，说明不能仅凭常驻量推算峰值，也不能把差异归因于 rank 一个变量。

旧文中的“约慢 4%”实际是**特定采样任务从 14 层增至 28 层**的耗时比较（52–53 秒对 53–55 秒），不是关闭交换与 28 层之间的训练速度差。

### 测试出图的显存策略

它管理**多个模型之间**谁让位（文本编码器 / DiT），与模型内部的 Block 交换是两件事，可以配合。在 **设置 → 测试 → 显存策略**：

- **默认（用后释放）**：命中的 prompt 缓存不重载文本编码器；新 prompt 根据实测编码峰值、空闲显存与 WDDM 预留量决定是否先把 DiT 移到内存。
- **省显存**：编码时强制让 DiT 与文本编码器顺序使用显存，小卡优先从这档试；仍需覆盖加载、编码、merge、采样与 VAE 解码的完整峰值。
- **性能优先**：尽量让模型常驻，减少等待，但需要更多显存余量。

**内存/显存水位保护**默认开启，尽力在加载前拦截可识别的资源不足；信息缺失、运行中其他程序占用或后续峰值仍可能导致 OOM / 换页。建议保持开启，但不要把它当作整机绝不卡顿的保证。

### LoRA merge 精度

fp8 底模挂 LoRA 时会把 delta **merge 进权重**。**设置 → 测试 → LoRA merge 精度**控制临时计算精度：

- **fp32**（默认）：对齐已验证版本的 ComfyUI merge 计算口径，不保证不同版本、硬件和工作流的最终图片逐位相同。
- **bf16**：降低临时 delta 的计算精度，可能改变合并结果；切换耗时与峰值收益需按实际配置测量，不是固定加速或显存减半。

两者采样时都使用合并后的 fp8 权重，因此不是改变采样权重存储大小的旋钮。普通 LoRA 有分块 merge 优化；LoHa / LoKr 的中间矩阵成本可能不同。Anima 与 bf16 底模走动态 LoRA，不受此选项影响。

完整测量条件与相关设计记录见 [训练技巧 → Block 交换](https://github.com/WalkingMeatAxolotl/AnimaLoraStudio/blob/master/docs/user-guide/training-tips.md#block-交换换出到内存的层数)。
